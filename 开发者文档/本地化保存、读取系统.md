# 本地化保存、读取系统

> **状态**：已完成  
> **最后更新**：2026-05-05  
> **关联文件**：`assets/editor-persistence.js`、`assets/editor-core.js`、`assets/annotation-store.js`、`references/html-template.md`

---

## 1. 概述

HTML-Slides 的本地化保存、读取系统允许用户直接在浏览器中编辑课件内容，并通过 **File System Access API** 将修改**固化到 HTML 源文件**中，同时保持交互组件的状态在刷新后自动重置。

**核心设计理念**：白名单模式——只保存用户明确编辑过的内容（`[data-edit-id]` 元素的 innerHTML），绝不保存任何组件的运行时交互状态。

---

## 2. 架构总览

```
┌─────────────────────────────────────────────────────┐
│                    页面加载时                         │

│                                                      │

├─────────────────────────────────────────────────────┤
│                    保存时                             │
│                                                      │
│  克隆 __BASELINE__                                   │
│    │                                                 │

```

## 3. 数据分层：内容、格式 vs 状态

系统将网页中的数据分为三类，**只保存内容和格式，绝不保存状态**：

| 类别 | 包含内容 | 存储位置 | 示例 |
|------|---------|---------|------|
| **内容** | 用户编辑的文字 | localStorage → HTML 文件 | 课件标题、卡片描述、选项文本 |
| **格式** | 富文本标记 | localStorage → HTML 文件 | `<strong>粗体</strong>`、`<span style="color:red">` |
| **状态** | 组件交互状态 | 仅内存，不持久化 | `.selected`、`.flipped`、`.step-active`、`disabled` |

**为什么状态不能保存？**
- 主分支原始 skill 只保存到 localStorage，刷新后组件 runtime 重新初始化，所有状态自然清零
- HTML 文件保存功能引入了"把脏数据写进源码"的风险
- 一旦状态被固化到 HTML 源码中，后续加载时 runtime 可能无法正确处理

## 4. 核心组件

### 4.1 干净基线快照 (`__BASELINE__`)

**位置**：HTML 文件中，`</div><!-- /deck -->` 之后、所有外部 `<script>` 之前

```html
</div><!-- /deck -->

<!-- ★ 干净 DOM 基线快照：在所有运行时 JS 执行前捕获 -->
<script>window.__BASELINE__=document.documentElement.cloneNode(true)</script>

<script src="./assets/slides-runtime.js"></script>
<script src="./assets/audio-runtime.js"></script>
...
```

**时机**：浏览器解析完整个 body（此时所有幻灯片 DOM 已存在），但所有外部脚本尚未执行。此时 DOM 完全干净——没有任何组件交互状态、编辑器 UI、导航圆点等运行时注入元素。

**作用**：保存时作为"原始干净结构"的底板。在此底板上只覆盖 `[data-edit-id]` 内容，天然保证不会把组件状态写入 HTML。

### 4.2 保存流程 (`saveToHTMLFile`)

**入口**：左上角保存按钮 或 Ctrl+S

```
saveToHTMLFile()
  │
  ├─ syncFromDOM(currentSlide)     —— 同步当前幻灯片到 localStorage
  │
  ├─ 有 __BASELINE__ ?
  │   ├─ YES → _prepareCleanHTMLFallback() （路径A：白名单）
  │   └─ NO  → _loadCleanHTMLFromDisk()    （路径B：旧课件兼容）
  │
  └─ _doWrite(html)
       │
       ├─ _htmlFileHandle 存在?     —— IndexedDB 恢复或首次选择
       │   ├─ YES → _writeHTMLToFile()
       │   └─ NO  → _requestHTMLFileAccess() → showSaveFilePicker()
       │
       └─ _writeHTMLToFile()
            ├─ createWritable()
            ├─ write(Blob)           —— < 1ms
            ├─ close()               —— fire-and-forget（不等）
            └─ return true
```

**路径A（白名单模式）详细步骤**：

1. `cloneNode(true)` 深拷贝 `__BASELINE__`（干净底板）
2. 遍历底板上所有 `[data-edit-id]` 元素，从 localStorage 读取已保存的 innerHTML 并覆盖
3. 从实时 DOM 补回 body 内的 `<script src>` 标签（基线捕获时它们尚未解析）
4. `_removeDeletedAnnotationNodes()` — 物理删除已删除批注的锚点节点
5. 设置第一张幻灯片为 `active`
6. 触发 `onExportClean` 钩子
7. `outerHTML` 序列化 + `<!DOCTYPE html>` 前缀
8. 写入磁盘

**关键优化**：
- **跳过 XHR**：有 `__BASELINE__` 时直接走白名单路径，不发 XHR 请求（file:// 下 XHR 必然失败且超时数秒）
- **close() fire-and-forget**：`FileSystemWritableFileStream.close()` 在 Windows + file:// 下会阻塞 7 秒刷盘。改为不等 close 完成就直接返回，用保存成功气泡的阻塞效果给 close 足够时间在后台完成
- **IndexedDB 持久化句柄**：刷新后自动恢复文件句柄，无需重新选文件

### 4.3 localStorage 保存 (`syncFromDOM`)

**触发时机**：幻灯片切换时自动保存当前页

```javascript
syncFromDOM: function (slideEl) {
    slideEl.querySelectorAll('[data-edit-id]').forEach(function (el) {
        PersistenceLayer.saveElement(el);  // innerHTML → localStorage
    });
    PersistenceLayer.saveCustomBoxes();    // 自定义图元位置
    PersistenceLayer.saveNativeMods();     // 原生元素位移/隐藏
}
```

**`saveElement` 中的清洗**：
`stripTransientEditableHTML()` 剥离嵌入在 `[data-edit-id]` 文本片段内的运行时瞬态标记：
- `qa-fragment-visible` — 批注 fragment 显隐
- `data-fragment-manual-reveal` — 手动展示标记

**仅此两种**。组件的交互状态（selected、flipped、step-active 等）不在 `[data-edit-id]` 内部，因此不会被保存到 localStorage。

### 4.4 读取流程 (`loadFromHTMLFile`)

```
loadFromHTMLFile()
  │
  ├─ 遍历 localStorage，清除当前课件所有键
  └─ location.reload()
       │
       └─ 浏览器从 HTML 文件重新加载
            ├─ 内容从 HTML 源码展示（上次保存的结果）
            ├─ 组件 runtime 重新初始化（所有交互状态清零）
            └─ 编辑器按钮由 _injectEditorUI() 重新创建
```

### 4.5 用户反馈

**保存气**泡：左上角三个按钮所在行居中显示，有弹入/淡出动画。

- 保存中：绿色 "⏳ 保存中..."
- 成功：绿色 "💾 保存成功" + `sound/pop.mp3` 音效
- 失败：红色 "❌ 保存失败"

**读取确认**：弹 confirm 对话框提醒用户将放弃未保存修改。

## 5. 文件句柄管理

### 5.1 IndexedDB 持久化

文件句柄在 `showSaveFilePicker()` 首次授权后存入 IndexedDB，刷新页面后自动恢复：

```javascript
// 存储
_persistHandleInDB(handle);

// 恢复（页面加载时自动执行）
(function _restoreHandleFromDB() {
    var req = indexedDB.open('hslides-fs-handle', 1);
    // ... 读取 'current' 键
})();
```

### 5.2 二次保存优化

`_doWrite` 函数处理三种场景：

| 场景 | `_htmlFileHandle` | 行为 |
|------|------------------|------|
| 首次保存 | null（无缓存） | `showSaveFilePicker()` 选文件 |
| 刷新后 | IndexedDB 恢复 | 直接 `createWritable()` 写入 |
| 写入失败 | 重置为 null | 回退 `showSaveFilePicker()` |

刷新后的首次保存**不再弹对话框**，因为句柄已从 IndexedDB 恢复。

## 6. 模板要求

所有生成的 HTML 课件**必须**满足以下要求（详见 `references/html-template.md`）：

### 6.1 基线快照脚本

在 `</div><!-- /deck -->` 之后、所有外部 `<script>` 之前：

```html
</div><!-- /deck -->

<script>window.__BASELINE__=document.documentElement.cloneNode(true)</script>

<script src="./assets/slides-runtime.js"></script>
...
```

### 6.2 HTML 规则

- 规则 6：所有外部 JS 必须用 `<script src>`（非 defer/async），因为基线在它们之前捕获
- 规则 9：必须在外部脚本前包含 `window.__BASELINE__` 快照脚本
- 快照脚本**不能**放在脚本之后，否则基线会包含运行时脏数据

## 8. 开发过程中的关键问题与解决方案

### 8.1 白屏问题（多次反复）

**根因**：保存后的 HTML 包含了运行时生成的 DOM 元素（导航圆点、翻页器、编辑器按钮），导致下次加载时元素冲突。

**解决历程**：
1. 最初尝试黑名单清洗 `_prepareCleanHTMLFallback` → 枚举不完所有交互状态
2. 尝试 `defer` 让脚本延迟执行 → 改变了脚本时序导致白屏
3. 尝试基线上追加第二个基线脚本 → 第二次加载时捕获了脏 DOM 覆盖干净基线
4. **最终方案**：基线快照在外部脚本前捕获（干净），保存时只覆盖 `[data-edit-id]`，从实时 DOM 补回脚本标签，不追加额外基线

### 8.2 保存后组件交互状态被固化

**根因**：旧 `_prepareCleanHTMLFallback` 从实时 DOM 复制 `el.innerHTML`，实时 DOM 包含运行时注入的 `selected`、`flipped`、`step-active` 等类。

**解决**：改为从 localStorage 读取 `[data-edit-id]` 内容（localStorage 中已经过 `stripTransientEditableHTML` 清洗）。基线底板本身不含组件状态。

### 8.3 保存缓慢（13 秒）

**根因**：
1. XHR 到 `file://` 超时数秒（已修复：有基线时跳过 XHR）
2. `FileSystemWritableFileStream.close()` 在 Windows + file:// 下阻塞 7 秒刷盘

**解决**：`close()` 改为 fire-and-forget（不等待），利用保存成功气泡的阻塞效果给 close 足够后台时间。

### 8.4 第二次保存失效

**根因**：`_writeHTMLToFile` 内部 `.catch()` 将 reject 转成了 resolve(false)，外部还在等 `.catch()` → 重试逻辑死代码。

**解决**：改为 `.then(writeOk => ...)` 检查返回值，失败时重置句柄重新请求。

### 8.5 保存后外部脚本标签丢失

**根因**：基线捕获时外部 `<script>` 标签尚未解析入 DOM。

**解决**：保存时从实时 DOM 的 `body script[src]` 补回脚本标签（排除 head 中的 CDN 脚本避免重复）。

### 8.6 刷新后仍弹文件选择框

**根因**：文件句柄在刷新后丢失（JavaScript 变量重置）。

**解决**：句柄存入 IndexedDB，页面加载时自动恢复。

### 8.7 旧版 `.annotations.js` 兼容

**解决**：完全移除。标注数据现在始终内联在 HTML + localStorage 中。`annotation-store.js` 简化为 30 行兼容存根。
