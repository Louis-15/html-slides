# 图片系统开发文档

> **版本**：1.0.0（2026-05-12）
> **概述**：html-slides 的图片系统采用"图片卡片 + 简单图片框"双层架构。图片引用统一使用外挂相对路径（`images/xxx.png`），替代旧版的 Base64 内嵌模式，并纳入完整的 localStorage 缓存 + HTML 文件持久化机制。

## 1. 架构总览

### 1.1 双层架构

```
图片系统
├── 类型A：图片卡片 (.image-card)
│   ├── Skill 原生生成，独占布局一栏
│   ├── 独立 CSS 文件 (zone2-image-card.css)
│   ├── 独立 JS 运行时 (image-card-runtime.js)
│   ├── 编辑按钮：🖼️ 插入/替换、🗑️ 清空
│   ├── 空态占位：保留布局位置
│   ├── 放映光箱：单击全屏预览 + 滚轮缩放 + 拖拽平移
│   └── 图片路径：images/xxx.png
│
└── 类型B：简单图片框 (.simple-image-box)
    ├── 用户通过工具栏插入，与文本框同级
    ├── 由 BoxManager 统一管理（editor-inline-boxes.js）
    ├── 与文本框共享 📍✖ 控件条
    ├── 排序拖拽（与文本框共享）
    ├── 宽度 100% 自适应父容器（流式混排）
    ├── 无八爪鱼缩放点
    └── 无光箱（仅 .image-card 有）
```

### 1.2 设计决策

| 决策 | 说明 |
|------|------|
| 外挂路径 | 所有图片引用 `images/xxx.png`，不再使用 Base64 内嵌。图片由用户提前放入 `课件/<课件名>/images/` 目录 |
| 持久化分层 | 编辑态 → localStorage（`saveElement`）→ 保存到 HTML（`saveToHTMLFile` / `exportCleanHTML`） |
| 两种类型分离 | 图片卡片是组件级，简单图片框是元素级（与文本框同级），互不干扰 |

## 2. 类型A：图片卡片（.image-card）

### 2.1 文件位置

- **CSS**：`assets/zones/zone2-image-card.css`
- **JS**：`assets/runtime/image-card-runtime.js`
- **暴露对象**：`window.ImageCardRuntime`

### 2.2 DOM 结构

#### 空态（无图时）
```html
<div class="image-card is-empty" data-image-slot="true">
  <div class="image-placeholder-icon"><!-- SVG: image-up --></div>
  <div class="image-placeholder-text">图片占位（编辑模式下点击图片图标按钮替换）</div>
</div>
```

#### 有图时（运行时自动切换）
```html
<div class="image-card">
  <img src="images/diagram.png" alt="说明图" class="slide-image">
  <div class="image-actions">
    <button class="image-card-replace-btn"><!-- SVG --></button>
    <button class="image-card-clear-btn"><!-- SVG --></button>
  </div>
</div>
```

### 2.3 CSS 文件结构 `zone2-image-card.css`

| 选择器 | 职责 |
|--------|------|
| `.image-card` | 基础布局：flex 列居中，`position: relative` |
| `.image-card .slide-image` | 图片尺寸约束（max-height: min(50vh, 400px)） |
| `.image-card:hover .slide-image` | 悬停放大效果 scale(1.01) |
| `.image-card.image-screenshot` | 截图变体：边框 + 阴影 |
| `.image-card.image-logo` | Logo 变体：更小的 max-height |
| `.image-fullbleed` | 全出血背景图片（绝对定位铺满） |
| `.image-overlay` | 全出血图片上的文字遮罩层 |
| `.image-card.is-empty` | 空态样式：虚线边框、居中占位 |
| `.image-card:not(.is-empty) .image-placeholder-*` | 有图时隐藏占位文字 |
| `.image-card .image-actions` | 编辑按钮容器（编辑态显示） |
| `.image-card-replace-btn` | 🖼️ 替换按钮 |
| `.image-card-clear-btn` | 🗑️ 清空按钮 |

### 2.4 JS 运行时 `image-card-runtime.js`

#### 方法清单

| 方法 | 作用 |
|------|------|
| `init()` | 初始化所有 `.image-card`：注入编辑按钮、同步空态、绑定光箱委托 |
| `_ensureStructure(block)` | 确保卡片内有 `.image-actions` 按钮容器，绑定替换/清空事件 |
| `_syncEmptyState(block)` | 检查 `<img>` 的 src 和 display 状态，同步 `is-empty` 类 |
| `_bindReplace(btn, block)` | 文件选择器 → 选择后调用 `_applyImageFile` |
| `_bindClear(btn, block)` | 清空 src + display:none + 写空 JSON 到 localStorage |
| `_applyImageFile(file, block)` | 验证文件名 → 构建 `images/xxx.png` 路径 → 写 src → 保存到 localStorage |
| `rehydrateSlide(slideEl)` | DOM 重建后重新初始化和同步空态 |
| `_initViewImageDelegate()` | 全局事件委托：放映模式点击图片弹出光箱 |

#### 光箱交互

- **触发**：放映模式（非编辑态）点击 `.image-card` 区域
- **背景**：`rgba(0,0,0,0.65)` + `backdrop-filter: blur(6px)`
- **缩放**：鼠标滚轮，范围 0.5x ~ 8x，步长 0.1
- **拖拽**：`pointerdown/move/up`，放大后按住拖拽平移
- **关闭**：Esc 键 / ✕ 按钮（单击不关闭，防误触）
- **样式保护**：`user-select: none` 防拖拽选中

## 3. 类型B：简单图片框（.simple-image-box）

### 3.1 文件位置

- **JS**：`assets/editor/editor-inline-boxes.js`（`BoxManager` 统一管理文本框 + 简单图片框）
- **CSS**：`assets/editor/editor.css`（与文本框共享 `.editable-wrap` 规则）
- **暴露对象**：`window.BoxManager`

### 3.2 设计说明

简单图片框**不是**一个独立的组件，而是**与文本框同级的可编辑流式元素**。用户通过编辑工具栏的图片按钮插入，自动包裹为 `.simple-image-box.editable-wrap`，与文本框共享同一套控件条、排序拖拽和删除逻辑。

### 3.3 DOM 结构

```html
<div class="simple-image-box editable-wrap" style="position: relative;">
  <img data-edit-id="simple-img-xxx" class="simple-image" src="images/xxx.png" style="width:100%;height:auto;max-width:100%;display:block;">
  <div class="box-controls" contenteditable="false">
    <span class="drag-handle" title="按住拖动📍">📍</span>
    <span class="del-btn" title="删除">✖</span>
  </div>
</div>
```

### 3.4 功能清单

| 功能 | 说明 |
|------|------|
| **创建** | 工具栏按钮 → 文件选择器 → `BoxManager.createSimpleImageBox(id, src, targetParent)` |
| **控件** | 与文本框共用 📍✖ 控件条（`.box-controls`），悬停时显示 |
| **排序拖拽** | 与文本框共用 `_bindDrag()`，带光标跟随半透明克隆体 + 绿色落点指示线 |
| **删除** | 与文本框共用 `_bindDelete()`，走 `isSimpleImage` 分支，提示"确定要删除这个图片框吗？" |
| **宽度** | `width: 100%` 自适应父容器，`height: auto` |
| **间距** | CSS `margin: 10px 0` 与相邻元素拉开距离 |
| **虚线框** | 复用 `.editable-wrap` 的 `outline` hover 虚线边框，`outline-offset: 0` |
| **缩放点** | ❌ 移除（原设计的八爪鱼缩放点已删除，决定让图片自适应父容器宽度） |
| **光箱** | ❌ 无（仅类型A 图片卡片有） |

### 3.5 创建流程

```
用户点击工具栏图片按钮
  ↓
弹出文件选择器
  ↓
选中文件 → 验证扩展名
  ↓
构建路径 images/xxx.png
  ↓
BoxManager.createSimpleImageBox('simple-img-xxx', 'images/xxx.png', targetParent)
  ├── 创建 <img data-edit-id> 追加到 targetParent
  ├── _injectControls(img)
  │   ├── 包裹 .simple-image-box.editable-wrap
  │   ├── 设置 position: relative
  │   ├── 注入 📍✖ 控件条
  │   └── 设置 width: 100%
  ├── PersistenceLayer.saveElement(img) → localStorage
  └── PersistenceLayer.saveCustomBoxes() → boxes 缓存
```

## 4. 加载顺序

### CSS 加载顺序

```
viewport-base.css → theme → components.css →
zone1-header.css → zone2-layout.css →
zone2-components.css → zone2-image-card.css → zone2-immersive-components.css →
...（quiz-annotation CSS）...
zone2-example-card.css → zone3-summary.css →
editor/editor.css
```

> `zone2-image-card.css` 必须紧接在 `zone2-components.css` 之后加载。

### JS 加载顺序

```
... → editor/editor-utils.js → editor/editor-persistence.js →
editor/editor-history.js → editor/editor-inline-boxes.js →
image-card-runtime.js → editor/editor-rich-text.js → editor/editor-core.js →
editor/editor-core-image.js →
page-richtext-annotation-runtime.js → doodle-runtime.js → ...
```

> `editor-inline-boxes.js` 替换了原来的 `editor-text-manager.js` + `editor-images.js`。
> `image-card-runtime.js` 必须在 `editor-inline-boxes.js` 之后、`editor-rich-text.js` 之前加载。

## 5. 初始化流程

### 5.1 图片卡片初始化（editor-core.js 中）

```
// 在 editorCore 构造函数之后、loadCustomBoxes 之前执行
ImageCardRuntime.init()
  ├── 遍历所有 .image-card
  │   ├── _ensureStructure(block)
  │   │   ├── 跳过已初始化的（通过 .image-actions 检测）
  │   │   └── 注入编辑按钮、绑定事件
  │   └── _syncEmptyState(block)  ← 即使 _ensureStructure 跳过也执行
  └── _initViewImageDelegate()
      └── 全局事件委托绑定（一次性）
```

### 5.2 简单图片框初始化

```
// EditorCore 构造函数中：
PersistenceLayer.restoreAllElements()    // 恢复 [data-edit-id] 内容
PersistenceLayer.restoreNativeMods()     // 恢复原生元素位移

// editorCore 构造函数之后：
BoxManager.init()                         // 扫描 [data-edit-id] 注入控件
PersistenceLayer.loadCustomBoxes()        // 恢复简单图片框
```

### 5.3 首次进入编辑模式（_ensureWrappersReady）

```
editorCore.toggleEditMode() → _ensureWrappersReady()
  ├── 为所有可编辑元素注入 wrapper（跳过 IMG）
  └── 调用 BoxManager._injectControls()
```

## 6. 持久化机制

### 6.1 localStorage 键值结构

| 键 | 格式 | 用途 |
|---|------|------|
| `hslides_<path>:e:<id>` | IMG：`{"html":"","src":"images/xxx.png"}`；文本：HTML 字符串 | 单个可编辑元素内容 |
| `hslides_<path>:boxes` | JSON 数组，每项含 `si/id/type/l/t/w/h/c/ip` | 自定义框位置/内容 |
| `hslides_<path>:nmods` | JSON 对象 `{id: {t, d}}` | 原生元素位移/隐藏 |

### 6.2 图片卡片持久化

```javascript
// 插入/替换图片时：
_applyImageFile(file, block) {
  // ...设置 src 和 data-edit-id...
  PersistenceLayer.saveElement(img)
  // → localStorage 保存为 {"html":"", "src":"images/xxx.png"}
}

// 清空图片时：
_bindClear(btn, block) {
  // ...清空 src 和 display...
  // → localStorage 保存为 {"html":"", "src":""}
  // （不删除 key，确保覆盖旧数据）
}

// 恢复时（restoreAllElements）：
// 读取 JSON → 解析 "src" 属性 → 设置 img.src
// 空 src 情况 → removeAttribute('src')
```

### 6.3 简单图片框持久化

#### 保存（saveCustomBoxes）

```javascript
// 遍历 .simple-image-box，记录：
{
  si: slideIndex,        // 幻灯片索引
  id: data-edit-id,      // 唯一标识
  type: 'image',         // 类型标记
  c: img.getAttribute('src'),  // 图片路径
  ip: "1,0"              // DOM 索引路径（用于恢复时定位父容器）
}
```

#### 恢复（loadCustomBoxes）

```javascript
// 1. 查找 data-edit-id 是否已在 DOM 中
// 2. 若已在 → appendChild 移到父容器末尾（恢复排序）
// 3. 若不在 → BoxManager.createSimpleImageBox() 创建
// 4. 父容器定位：优先 ip（DOM 索引路径），回退 .slide-content
```

### 6.4 导出清洗

在 `exportCleanHTML` / `saveToHTMLFile` 的清洗逻辑中：
- 移除 `.save-bubble` 和 `input[type="file"]`（运行时残留）
- 移除 `.image-actions`（编辑按钮不写入 HTML）
- 移除 `.box-controls` 和 `.rs-handle`（控件条不写入 HTML）
- 安全样式注入 `.image-actions { display: none !important }`

## 7. 交互合同

### 7.1 键盘导航

图片卡片属于被动组件，参与顶层面板焦点顺序（`↑/↓`），展示 `.step-active` 但没有自身的 forward 动作。`←/→` 保留给当前焦点宿主内部的 fragment 步进。

### 7.2 编辑模式

| 元素 | 编辑态行为 |
|------|-----------|
| `.image-card` + 🖼️ 按钮 | 编辑模式显示，放映模式隐藏 |
| `.image-card` + 🗑️ 按钮 | 清除图片，保留 `.image-card` 框 |
| `.simple-image-box` 📍手柄 | 编辑模式显示，按住排序拖拽 |
| `.simple-image-box` ✖ 按钮 | 编辑模式显示，删除整个 `.simple-image-box` |

### 7.3 与 Doodle 模式的互斥

进入编辑模式时，如果涂鸦模式处于开启状态，强制退出。反之亦然。
