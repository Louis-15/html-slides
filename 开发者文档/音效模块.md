## 一、系统定位

音效模块负责为课件运行时提供一条**轻量、可复用、可静音**的提示声通路。

它不负责配乐，不负责时间轴混音，也不负责把“每个组件该在什么时候响”写死在一个总开关里。当前架构已经明确拆成三层：

- `assets/audio/audio-runtime.js`：全局音效总线。负责 cue 名称注册、音频资源映射、播放路径选择、模式静音开关与调试状态。
- `assets/slides-runtime.js`：顶层 cue 调用方。负责在一级焦点切换、翻页、summary 打开、flip 正向翻转、collapse 正向展开时触发全局 cue。
- 组件 / 宿主侧分成两路：
  - `assets/quiz-annotation-audio.js`：把 quiz 组件里的“片段前进 / 片段后退 / hover 提示”翻译成对全局 cue 的调用；
  - `assets/page-richtext-annotation-runtime.js`：普通页面隐藏型富文本标注直接调用 `AudioRuntime.playGlobalCue()` 播放片段前进 / 片段回退 / hover 提示声。

这套拆分的核心目标有三个：

1. 组件层只关心“我要播什么 cue 名称”，不关心底下具体是 mp3、flac 还是未来换素材。
2. 编辑模式必须全局静音，避免排版与课堂放映提示声互相打架。
3. 独立课件常常直接以 `file://` 打开，因此播放链路必须兼容本地文件安全限制，不能把能力完全押在 Web Audio API 上。

                       │
        ┌──────────────┴──────────────┐
        │                             │
┌───────▼────────────────┐   ┌────────▼───────────────────────┐

## 三、AudioRuntime 设计

### 3.1 cue 预置表

`audio-runtime.js` 只维护“cue 名称 -> 实体音频资源”的映射。当前内置 8 个预置：

| cue 名称 | 资源文件 | 默认增益 | 当前用途 |
|---------|----------|----------|----------|
| `focus-shift` | `assets/audio/sound/pop.mp3` | 2 | 一级焦点切到可互动宿主 |
| `page-turn` | `assets/audio/sound/turn_page.mp3` | 1 | 真正发生翻页时 |
| `summary-open` | `assets/audio/sound/cash_register.mp3` | 1.5 | summary panel 正向打开（带 471ms 起播裁剪） |
| `flip-forward` | `assets/audio/sound/flip.mp3` | 1 | flip-card 正向翻转 |
| `collapse-expand` | `assets/audio/sound/drawer.mp3` | 1 | collapse-card 正向展开 |
| `fragment-swoosh` | `assets/audio/sound/whoosh.mp3` | 2 | 片段前进揭示 |
| `fragment-swoosh-back` | `assets/audio/sound/whoosh_back.mp3` | 2 | 片段后退回收 |
| `ui-hover` | `assets/audio/sound/annotation_hover.flac` | 5 | 片段 hover 提示 |

组件层只应引用这些 cue 名称，而不应直接硬编码音频文件路径。

### 3.2 全局 API

当前暴露到 `window.AudioRuntime` 的核心接口如下：

- `isEnabled()`：判断当前模式下是否允许播放。
- `getCueDefinition(name)`：返回某个 cue 的只读定义。
- `playPreset(name)`：直接播放一个全局预置 cue。
- `playGlobalCue(name)`：语义化别名，当前内部仍走 `playPreset()`。
- `registerComponentCue(componentName, cueName, handler)`：给某个组件注册 cue 处理函数。
- `playComponentCue(componentName, cueName, payload)`：播放组件级 cue。
- `getDebugState()`：输出最近一次播放的 cue 名、播放器类型、错误信息与当前协议。

### 3.3 模式开关

音效总线当前只识别三种运行态：

- 编辑模式：静音。
- 普通放映模式：允许播放。
- 涂鸦模式：允许播放。

编辑模式静音并不是由每个组件各自判断，而是由 `AudioRuntime.isEnabled()` 统一拦截。这样可以保证以后新增组件时不会漏掉静音规则。

### 3.4 HTTP(S) 与 file:// 的双路径播放

这是当前音效模块最关键的工程决策之一。

在 HTTP(S) 或本地服务场景下，`audio-runtime.js` 优先走 **Media Graph 路径**：

- 通过 `AudioContext` + `createMediaElementSource()` + `GainNode` 做真实增益。
- 这样可以把 2x / 5x 的 cue 放大量化成统一的数字增益。

但独立课件通常直接双击打开，运行在 `file://` 协议下。此时把本地媒体接入 Web Audio API，在部分浏览器里会直接抛 `SecurityError`，或者表现成“看起来播放了但实际上静音”。

因此本地模式必须回退到 **fan-out 普通音频并发** 路径：

- 根据目标增益拆成若干个普通 `Audio` 实例。
- 多路并发播放，近似实现“放大后的响度”。
- 优先保证“能听见”，而不是追求最理想的数字增益链路。

调试时可以用 `AudioRuntime.getDebugState()` 判断最近一次播放走的是 `media-graph` 还是 `fan-out`。

## 四、QuizAnnotationAudio 组件适配层

`quiz-annotation-audio.js` 是一层非常薄的翻译层，它只做两件事：注册 cue，以及在组件代码里提供更语义化的调用入口。

### 4.1 注册协议

组件名固定为 `quiz-annotation`，当前注册了两个 cue：

- `fragment-step`
  - `direction === 'forward'` -> `fragment-swoosh`
  - `direction === 'backward'` -> `fragment-swoosh-back`
- `fragment-hover`
  - 固定映射到 `ui-hover`

### 4.2 对外调用接口

当前暴露到 `window.QuizAnnotationAudio` 的接口有：

- `registerCues()`
- `playFragmentStep(payload)`
- `playFragmentHover(payload)`

### 4.3 hover 节流

hover 声会按 `linkId` 做 160ms 冷却节流：

- 同一个锚点在极短时间内反复触发 hover，不会连续刷屏式发声。
- 不同 `linkId` 之间仍可正常各自触发。

这条节流既适用于普通放映模式，也适用于 doodle hit-test 代理出来的 hover 通路。

## 五、运行时触发点

当前真正联动音效模块的调用点已经覆盖了顶层步进、普通页隐藏标注和 quiz 组件三条路径：

### 5.1 一级焦点切换（`slides-runtime.js`）

当一级焦点在两个不同宿主之间切换，且**目标宿主本身可互动**时，`slides-runtime.js` 会调用：

```javascript
window.AudioRuntime.playGlobalCue('focus-shift')
```

这个语义已经从“任何一级焦点变化都响”收紧为“提醒用户当前宿主可互动”。因此普通展示组件根虽然也进入一级队列，但不会发出 pop。

### 5.2 翻页与顶层互动（`slides-runtime.js`）

`slides-runtime.js` 还负责触发以下顶层 cue：

- 真正翻到新页时：`page-turn`
- summary 正向打开时：`summary-open`（必须在 panel 变成 visible 之前先播）
- flip-card 正向翻转时：`flip-forward`
- collapse-card 正向展开时：`collapse-expand`

这几个 cue 都只服务正向动作；反向撤销（如收起、翻回正面、ArrowUp 回退）当前保持静音。

### 5.3 普通页面隐藏型富文本标注（`page-richtext-annotation-runtime.js`）

普通页运行时没有再单独引入一层组件音效适配文件，而是直接调用全局总线：

```javascript
window.AudioRuntime.playGlobalCue('fragment-swoosh')
window.AudioRuntime.playGlobalCue('fragment-swoosh-back')
window.AudioRuntime.playGlobalCue('ui-hover')
```

对应语义为：

- `ArrowRight` / `ArrowLeft` 在当前焦点宿主内部揭示或回退 authored fragment；
- 鼠标 hover 到拥有隐藏标注的普通 `data-edit-id` 根块时，播放 `ui-hover`；
- doodle 模式下通过 hit-test 透传到底层普通文本根块时，也走同一套 hover / fragment cue。

### 5.4 答题与批注组件（`zone2-quiz-annotation/` 17 JS 子模块 + `quiz-annotation-audio.js`）

quiz 组件继续保留自己的适配层：

```javascript
window.QuizAnnotationAudio.playFragmentStep({ direction, reason })
window.QuizAnnotationAudio.playFragmentHover({ linkId, ... })
```

其中：

- `forward` -> `fragment-swoosh`
- `backward` -> `fragment-swoosh-back`
- hover -> `ui-hover`

quiz 顶层 bubble 焦点切换仍然通过 `AudioRuntime.playGlobalCue('focus-shift')` 触发，但它不受普通页“先聚焦、后互动”两步模型影响。

### 5.5 doodle 模式下的间接触发

在涂鸦模式中，hover / 右键揭示并不是直接落在底层 DOM 上，而是先经过 doodle hit-test 解析，再由普通页宿主或 quiz 宿主代理触发。音效模块对这一层完全无感，只要最终有人调用 `playGlobalCue()`、`playFragmentHover()` 或 `playFragmentStep()` 即可。

## 六、HTML 引用顺序

课件脚本加载建议按下面顺序组织：

```html
<script src="./assets/runtime/navigation.js"></script>
<script src="./assets/runtime/keyboard.js"></script>
<script src="./assets/runtime/step-through.js"></script>
<script src="./assets/runtime/chart-integration.js"></script>
<script src="./assets/runtime/speaker-notes.js"></script>
<script src="./assets/audio/audio-runtime.js"></script>
<script src="./assets/audio/quiz-annotation-audio.js"></script>
<script src="./assets/runtime/zone2-quiz-annotation/quiz-init.js"></script>

<script src="./assets/editor/editor-utils.js"></script>
<script src="./assets/editor/editor-persistence.js"></script>
<script src="./assets/editor/editor-history.js"></script>
<script src="./assets/editor/editor-text-manager.js"></script>
<script src="./assets/editor/editor-images.js"></script>
<script src="./assets/editor/editor-rich-text.js"></script>
<script src="./assets/editor/editor-core.js"></script>
<script src="./assets/runtime/page-richtext-annotation-runtime.js"></script>
<script src="./assets/runtime/doodle-runtime.js"></script>
```

顺序说明：

- `audio-runtime.js` 必须早于所有会发声的运行时。
- `audio-runtime.js` 必须先于 `quiz-annotation-audio.js`，因为组件适配层要在加载时向全局总线注册 cue。
- `zone2-quiz-annotation/` 的 JS 模块必须晚于 `quiz-annotation-audio.js` 加载。加载顺序按依赖拓扑排列（见 `qa-test-all-types.html` 的 `<script>` 顺序）。
- `page-richtext-annotation-runtime.js` 依赖 `slides-runtime.js` 暴露出的 refresh / activate hook，也依赖 `AudioRuntime` 在放映态播放 fragment cue；它可以像当前真实课件那样放在 `editor/editor-core.js` 之后、`doodle-runtime.js` 之前。
- 编辑器与涂鸦模块继续保持在 quiz 运行时之后加载，沿用原有依赖顺序。

## 七、测试与排障

### 7.1 当前测试覆盖

仓库里已有专项测试：

- `testing/tests/audio-runtime.test.js`
- `testing/tests/quiz-annotation-runtime.test.js`
- `testing/tests/slides-runtime.test.js`

这些测试当前覆盖了：

- cue 定义是否存在；
- HTTP(S) / `file://` 双路径回退是否成立；
- 普通页面隐藏型标注是否会在正确时机播放 fragment step / hover cue；
- 组件适配层是否正确把 fragment step / hover 翻译成 cue 播放；
- 放映运行时是否在正确时机调用这些接口。

### 7.2 常见排障点

1. 普通放映模式 hover 没声音，但 doodle 模式有声音。
原因通常是旧版把“已绑定 hover 监听”写成了 DOM 持久化属性。当前正确做法是只用运行时私有标记。

2. 本地双击打开的课件完全静音。
优先检查是否误删了 `fan-out` 回退逻辑，或者把播放强行绑死在 `createMediaElementSource()` 路径上。

3. 编辑模式里操作文字时也在响。
说明模式静音入口被绕过了。应统一走 `AudioRuntime.isEnabled()`，而不是让组件自己判断是否要播。

4. 组件想新增音效。
不要直接 new 一套播放器。先把资源接到 `audio-runtime.js` 的 `cueDefinitions`，再通过 `registerComponentCue()` 暴露给组件层。

一句话总结设计哲学：**全局总线只管“有什么声音、现在能不能响”，组件适配层只管“什么时候触发哪一个 cue”。**
