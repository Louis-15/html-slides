## 一、系统定位与设计初衷

在 HTML 幻灯片生态中，如果说 Zone2 布局管的是“空间与排版”，Editor 引擎管的是“破坏与重建”，那么放映系统（Runtime）掌管的就是**时间维度**与**视觉动效**。

它由 JavaScript 引擎（`navigation.js` + `keyboard.js` + `step-through.js` + `chart-integration.js` + `speaker-notes.js`）与全局 CSS 关键帧动画（`components.css` 中的 `@keyframes` 及各主题包中的绑定）共同构成。

**这一层的核心职责是绝对纯粹的：**
只负责控制哪一张幻灯片（Slide）该出现在观众面前、哪一个碎片（Step）该按顺序点亮，以及负责协调极其脆弱的入场动画体系，确保放映过程丝滑、不串台。

### 1.1 2026-04-25 键位、焦点与导航最新合同

- 全局步进已经稳定为**一级/二级双层模型**：`↑↓` 负责当前页顶层组件焦点，只有当前页的顶层焦点耗尽后才翻页；`←→` 只交给“当前焦点宿主”内部的片段步进。
- 一级交互队列不再只收 `data-steppable` 互动体，而是同时纳入两类来源：
    1. 普通页 `slide-content` 里按插槽结构自动发现的组件根（如 `card`、`stat-card`、`timeline-card`、`code-window`、`chart-container`、`table-wrap`、`image-block`、`dual-bar`、`content-block` 等）；
    2. 显式注册的 `data-steppable` 宿主（如 `flip-card`、`collapse-card`、`summary-trigger`、`page-richtext-host`、`quiz-annotation`）。
- 普通页互动组件统一采用**先聚焦、后互动**的两步模型：第一次 `ArrowDown` 只把焦点落到组件根，第二次 `ArrowDown` 才执行翻转 / 展开 / summary 打开；`ArrowUp` 先撤销当前组件状态，再下一次才离开该组件。
- 鼠标左键点击任意一级队列组件后代时，也会把一级焦点同步到该组件根；对 `flip-action-btn`、`collapse-action-btn`、`summary-trigger` 这类直接互动按钮，则走“静默切焦点 + 立即执行 forward/backward”的捷径。
- `example-card` 现已并入放映底座的专项宿主：当当前 slide 上存在例题组件时，`ArrowDown` / `ArrowUp` 被重新解释为“下一题 / 上一题”，不会在题卡边界触发整页翻页；而 `ArrowLeft` / `ArrowRight` 会被钉死到**当前显示题目的左栏 `.example-card__main`**，只服务这道题已经提交后的 ordinary fragment reveal。
- `quiz-annotation` 明确排除在这轮普通页 redesign 之外：它仍保留“第一次 `ArrowDown` 落到宿主时就自动推进到第一个 bubble”的旧语义，避免答题页的顶层体验被普通页新合同误伤。
- 全局右下角 `slide-pager` 翻页按钮继续常驻于编辑、放映、涂鸦三种模式；按钮禁用态仍随 `current` 页索引实时刷新。

### 1.2 2026-04-25 音效与 page-richtext 协同补充

- 放映系统继续只负责“什么时候切换顶层焦点 / 什么时候执行片段步进”；真正的音源管理下沉到 `assets/audio/audio-runtime.js`，组件适配层拆成两路：
    1. `navigation.js` 直接触发顶层 cue（`focus-shift`、`page-turn`、`summary-open`、`flip-forward`、`collapse-expand`）；
    2. `zone2-quiz-annotation/` 的 JS 模块与 `page-richtext-annotation-runtime.js` 各自处理片段步进与 hover cue。
- `focus-shift` 的语义已经收紧：只有一级焦点真的切到**可互动宿主**时才播放；普通展示组件根虽然也会进入一级队列，但只显示 `.step-active`，不再发出 pop。
- `summary-open` 必须在 summary panel 真正 visible 之前先播放；`flip-forward` 与 `collapse-expand` 只服务正向动作，反向撤销保持静音。
- 普通页隐藏型富文本标注已经通过 `assets/runtime/page-richtext-annotation-runtime.js` 接入运行时：当当前焦点宿主自己的 `stepFragment()` 不消费 `←→` 时，`step-through.js` 会把这次片段步进 fallback 给普通页宿主；quiz 页整页早退，不让普通页 fallback 抢占答题组件的片段协议。
- `example-card` 的提交结果音效通过 `assets/audio/example-card-audio.js` 把“本题答对 / 答错”的业务语义翻译成全局 `answer-correct` / `answer-wrong` cue；题内翻题则复用全局 `page-turn` cue，避免再维护一套内容相同的独立素材映射。
- `AudioRuntime.isEnabled()` 仍是统一总开关：编辑模式静音，普通放映与涂鸦模式允许播放。

## 二、架构总览与时间流逝机制

整个放映动效系统的运转，依托于一个极其极简的**“类开关协议”**：

```text
┌──────────────────────────────────────────────────────────────┐
│              navigation.js + step-through.js               │
│  [键盘监听] / [滚轮防抖] / [小圆点点击]                        │
└──────────────────────┬───────────────────────────────────────┘
                       │ 唯一通信信使：.active 类
┌──────────────────────┴───────────────────────────────────────┐
│                    DOM 层级状态切换                           │
│  <div class="slide active">   → 当前放映页 (Z-index 最高)      │
│  <div class="slide">          → 背景沉睡页 (Z-index 隐藏)      │
└──────────────────────┬───────────────────────────────────────┘
                       │ 级联触发 CSS 动画
┌──────────────────────┴───────────────────────────────────────┐
│                    CSS 渲染管线 (主题 / components.css)      │
│  .slide.active .anim-1 { animation: slideUp ... }            │
│  .slide.active .step.active { animation: fadeIn ... }        │
└──────────────────────────────────────────────────────────────┘
```

**设计铁律：JS 绝不直接操作元素的几何属性进行翻页/入场计算。** 所有的动画编排、时间轴延迟（Delay），全部交给浏览器的 CSS 渲染管线处理。JS 只充当拨动开关的“手”。

### 2.1 翻页底座机制：Z轴透明叠片架构
与传统的强制滚动 (`scrollIntoView`) 不同，我们的引擎彻底抛弃了滚动条物理位移，而是采用了**“Z轴叠片（Cross-fade Stack）”**架构：
1. **全员绝对定位层叠**：在 `components.css` 中，所有的 `.slide` 都被赋予了 `position: absolute; inset: 0;`。这意味着如果一份课件有 50 页，它们在 DOM 物理结构下是完全叠在同一个 X/Y 坐标上的。
2. **默认透明休眠**：所有的基础 `.slide` 均自带 `opacity: 0; pointer-events: none;`。这就如同 50 张全透明的玻璃板。没有焦点，没有阻挡，没有内容渲染压力。
3. **点亮即现身**：当且仅当 JS 的引擎为幻灯片加封 `.active` 王冠时，CSS 选择器 `.slide.active` 赋予其 `opacity: 1; pointer-events: auto;`。此时，带有 `transition: opacity 0.45s` 缓冲属性的页面将以极其丝滑的交叉渐变（Cross-fade）形式跃然荧幕，并一并唤醒该玻璃板内所有随属组件的入场小动画。

## 三、三维导航与步进系统 (Stepping)

幻灯片的放映不仅仅是 2D 的页与页切换，内部还嵌套了步骤进阶（Fragment / Stepping）。

### 3.1 导航防抖与降噪
原生的 `wheel`（滚轮）和 `touchmove`（触摸）事件触发频率高得惊人。为了防范用户稍微滑一下鼠标滚轮连翻十页的灾难：
- 引擎内置了严格的**时间戳防抖锁（Debounce Lock）**，两次翻页之间存在物理时间冷却（例如 500ms）。
- 绝不因动画没播完而卡死逻辑，翻页指令是最高优先级的，随时可以直接掐断当前动画强行跳转新界面。

### 3.2 一级/二级步进队列算法 (Interaction Queue)
当前 runtime 已经不再依赖旧的 `.step` 子节点矩阵，而是维护一个“当前页顶层宿主队列 + 当前宿主片段步进”的双层协议：

1. `buildInteractionQueue()` 会把普通页结构发现出来的组件根，与显式 `data-steppable` 宿主合并后按文档顺序去重。
2. `setInteractionFocusIndex()` 负责切换一级焦点，并给当前宿主挂上 `.step-active`；只有目标宿主本身是互动体时，才会额外播放 `focus-shift`。
3. `stepForward()` 先尝试当前宿主的顶层 forward；如果当前宿主没有更多顶层动作，再把一级焦点移到下一个宿主。普通页因此形成“先聚焦、后互动”的两步模型；只有 quiz 页仍然在首次落焦时自动 forward。
4. `stepBackward()` 先检查当前宿主是否还处于可回退状态。普通页互动宿主在第一次 `ArrowUp` 时只撤销当前动作但保留焦点；只有回退状态清空后，再下一次 `ArrowUp` 才真正离开该宿主。quiz 页继续保留旧语义。
5. `stepFragment(direction)` 先把 `←→` 交给当前一级焦点宿主自己的 `strategy.stepFragment()`；如果当前宿主不消费，并且当前页不是 quiz，则再 fallback 给 `PageRichTextAnnotationRuntime.stepFragment(direction, currentSlide, currentFocusedElement)`，从而让普通页隐藏型富文本标注严格挂在“当前一级焦点组件”之下。

### 3.3 鼠标点击与外部运行时协同

- `findInteractionQueueElement()` 不再只沿着 `data-steppable` 祖先链向上找，而是统一从当前页 `interactionQueue` 中反查“点击命中的真实组件根”，确保 passive root、互动体、summary-host、page-richtext-host 都走同一套一级焦点合同。
- `activateInteractionStepForElement()` 与 `refreshInteractionQueueForCurrentSlide()` 是专门暴露给后加载运行时的最小协同接口：
    - `page-richtext-annotation-runtime.js` 在作者态新增/删除片段后，会用 refresh hook 重新同步宿主资格；
    - quiz / ordinary page 的右键 reveal 与点击路径，也都可以通过 activate hook 把一级焦点显式对齐到真实宿主。
- `summary-trigger` 是这一层最特殊的宿主：按钮本体先作为一级焦点对象显示 `.step-active`，第二次 `ArrowDown` 才会把 `summary-panel` 打开；而 `summary-panel` 内 authored 的普通页片段又会反向把宿主归属到 `summary-trigger`，保证 `←→` 仍然挂在按钮焦点之下，而不是把面板里的 `<li data-edit-id>` 错误塞成新的一级焦点项。

## 四、入场动效系统与 CSS 特异性架构

为了让数以百计的组件不用被挨个手动调配动画，我们采取了**阶梯式联级动画宣告**。

### 4.1 动画库 (components.css)
定义了基础物理学规律库，比如弹性升起、玻璃破裂、极速滑入等纯关键帧定义（`@keyframes slideUpElastic`）。

### 4.2 主题绑定层 (themes/*.css)
主题掌控了哪些组件该在什么时候入场。
通过设定高度的 CSS 特异性：
```css
.slide.active .layout-single > * {
    animation: fadeUp 0.8s ease forwards;
}
.slide.active .anim-1 { animation-delay: 0.1s; }
.slide.active .anim-2 { animation-delay: 0.2s; }
```
**原理**：只要父元素 `.slide` 失去了 `.active`，由于选择器条件不成立，子元素身上的 animation 属性瞬间瓦解。而在下一次被重新赋予 `.active` 时，由于规则重新生效，浏览器将其视作一个处于初始状态的全新节点，再次从 0 毫秒开始放映一遍入场动画。

## 五、核心避坑实录：动画与编辑的“不死之争”

在打通 `editor-core` (动态编译引擎) 与此放映引擎时，最剧烈的冲突爆发了。

### 🔥 致命冲突：DOM 重挂载导致的疯狂重播
**背景描述**：
当初次进入编辑模式时，编辑器需要在底层为每个支持编辑的组件套上一个 `.native-edit-wrap` 隔绝层框。在浏览器视角，这属于把旧节点拔出来重新塞回去（DOM Re-mount）。紧接着退出编辑模式时，又需要把框子拆除再塞回去。
**灾难现象**：
每一次进出编辑模式，所有的幻灯片由于被视为“新挂载”，无视了之前已经播放完毕的状态，集体重新重播了一遍轰轰烈烈的入场动画，导致排版发生极严重的视觉震荡（闪烁位移）。

### 🛡️ 高级抑制协议的诞生
为了镇压原生底层的这股反扑，我们放弃了暴力的 `animation: none`，创立了**“运行时动画降维冻结协议”**。技术路径如下：

#### 策略 1：Z轴阻绝机制 (CSS Paused)
```css
/* 压制规则优先级超越普通主题动画 (0,3,1) vs (0,3,0) */
html.editor-mode .slide.active *,
html.editor-mode .slide.active *::before,
html.editor-mode .slide.active *::after {
    animation-play-state: paused !important;
}
```
不再采用 `none` 把动画抹除（那会导致退出时动画视为新生而重播），而是采用**暂停策略** (paused)。
这使得所有在编辑环境下的元素，其动画状态定格在了当前的最终结果上。它就在那里，但被按了暂定键。

#### 策略 2：瞬步击杀机制 (Web Animations API)
然而，首次注入 Wrapper 以及进行 Undo/Redo (撤销重做引发 `innerHTML` 重写) 时的瞬间，新的 DOM 是没有历史积累时间轴的，一旦建立它们会在毫秒内尝试从头播放。
借此引入了现代 JS Web 动效抹杀能力：
```javascript
if (slide.getAnimations) {
    try {
        slide.getAnimations({ subtree: true }).forEach(a => a.finish());
    } catch(e) {}
}
```
这句话能一键抓取发生重排后试图启动的所有子帧动画，并在第 1 毫秒时利用 `.finish()` 将它们的时间轴直接拉拽到大结局尽头。

这两套连招让动态组件引擎与静态动效引擎签下了互补协议，让课件实现了“编辑动作瞬间完成，毫无花哨残影”的超工业级所见即所得体验。
