## 一、组件定位

例题组件是 html-slides 里专门服务“单页讲题 / 多题连讲 / 提交后再揭示解析”的轻量答题卡片。它和 `.quiz-annotation` 的区别非常明确：

- `.quiz-annotation` 是整页三栏系统，左栏阅读、右栏作答、中栏批注同时存在；
- `.example-card` 是**单卡片系统**，视觉上只有题面与解析两块，重点是“先做题，再讲题，再切下一题”；
- `.example-card` 可以在一张卡里串多道题，但它不会生成中栏批注面板，也不会接入 quiz 的 SVG 连线、bubble 与 linkId 模型。

当前组件适合的课堂场景：

- 听力单题讲解
- 阅读理解例题拆讲
- 语法选择题、多选题、不定项选择题、填空题示范
- 同一知识点下连续 2-5 道题的“上一题 / 下一题”串讲

## 二、文件归属与依赖栈

### 2.1 样式与运行时

- 样式：`assets/zones/zone2-example-card.css`
- 音效适配：`assets/example-card-audio.js`
- 运行时：`assets/example-card-runtime.js`
- 相关测试：`testing/tests/example-card-runtime.test.js`

### 2.2 推荐加载顺序

例题组件不是纯 CSS 卡片。要保证编辑态退出守卫、ordinary fragment 刷新、题内翻题键盘合同都正常生效，脚本顺序应按下面理解：

1. `slides-runtime.js`
2. `audio-runtime.js`
3. `example-card-audio.js`
4. `annotation-store.js`（如果页面本身还需要 sidecar 恢复能力）
5. `editor-utils.js → editor-persistence.js → editor-history.js → editor-box-manager.js → editor-rich-text.js → editor-core.js`
6. `page-richtext-annotation-runtime.js`
7. `doodle-runtime.js`
8. `example-card-runtime.js`

其中第 8 步必须晚于 `editor-core.js`，否则运行时第一次初始化时拿不到 `editorCore.toggleEditMode()`，多选题“至少两个正确答案”的编辑态退出守卫就不会被补丁接管。

## 三、HTML 结构合同

### 3.1 单题最小结构

```html
<section class="example-card" data-card-id="ec-01" data-question-type="single">
  <article class="example-card__question is-active" data-question-id="ec-01-q1" data-question-active="true" data-question-submitted="false">
    <div class="example-card__main">
      <div class="example-card__stem" data-edit-id="ec-01-q1-stem">
        23. What was the speaker's original plan for the small garden?
      </div>

      <div class="example-card__answers">
        <button type="button" class="qa-option example-card__option" data-option-value="A">
          <span class="qa-option-label">A</span>
          <span class="qa-option-text" data-edit-id="ec-01-q1-option-a">Grow tomatoes only.</span>
        </button>
        <button type="button" class="qa-option example-card__option" data-option-value="B" data-correct="true">
          <span class="qa-option-label">B</span>
          <span class="qa-option-text" data-edit-id="ec-01-q1-option-b">Make a quiet reading corner.</span>
        </button>
      </div>
    </div>

    <aside class="example-card__analysis" hidden>
      <div class="example-card__analysis-title">解析</div>
      <div class="example-card__analysis-body" data-edit-id="ec-01-q1-analysis">
        题干里的 original plan 对应原文前半句，因此答案选 B。
      </div>
    </aside>

    <div class="example-card__footer">
      <div class="example-card__nav">
        <button type="button" class="example-card__prev-btn" disabled>上一题</button>
        <button type="button" class="example-card__next-btn" disabled>下一题</button>
      </div>
      <div class="example-card__actions">
        <button type="button" class="example-card__analysis-toggle" disabled>查看解析</button>
        <button type="button" class="example-card__submit-btn">提交答案</button>
      </div>
    </div>
  </article>
</section>
```

### 3.2 多题结构

- 一张卡内部可以包含多个 `.example-card__question`
- 只有当前题目去掉 `hidden`，并打上 `data-question-active="true"`
- 其它题目必须保留 `hidden aria-hidden="true"`
- 题目切换按钮统一放在各题共享的 `.example-card__footer` 内

运行时当前明确依赖 `.example-card__question[hidden] { display: none !important; }` 这条 CSS 合同。因为题目壳层本身是 `display:grid`，如果不显式补回 hidden 行为，多题 DOM 会叠在同一格里互相遮挡。

## 四、当前支持的题型

例题组件现在正式支持 4 种题型：

| 题型值 | 胶囊文案 | 学生态选择模型 | 编辑态正确答案模型 |
|--------|----------|----------------|--------------------|
| `single` | 单选 | 只保留一个 `selectedValues` | A/B/C/D 单选答案键 |
| `multi` | 多选 | 集合式多选 | A/B/C/D 多选答案键，且至少两个正确答案 |
| `flex` | 不定项选择 | 集合式多选 | A/B/C/D 答案键，允许 1 个或多个正确答案 |
| `blank` | 填空 | 当前只做 reveal，不采集学生输入 | 横线输入框直接编辑标准答案 |

### 4.1 为什么 `multi` 和 `flex` 在学生态都按集合式处理

这不是实现偷懒，而是课堂语义决定的：

- 多选与不定项选择的差异在**作者态约束**，不在学生态点击模型；
- 进入学生作答阶段后，这两类题都必须保留“已选集合”，否则不定项选择会退化成伪单选；
- 提交后错选项之所以能显示红态，也依赖这份完整的 `selectedValues` 集合。

### 4.2 blank 题的现状

- 学生态 blank 当前只负责“提交后揭示标准答案”，不做对错判定；
- 编辑态 blank 不再显示 A/B/C/D 答案键，而是显示 `.example-card__blank-answer-input`；
- 标准答案保存在 `.example-card__blank[data-correct-answer]` 上，并额外写入作者态快照。

## 五、编辑态合同

### 5.1 三条编辑 UI

运行时会在题目主区按需注入三条作者态辅助行：

- `.example-card__editor-type-picker`：题型胶囊
- `.example-card__editor-answer-key`：选择题答案键
- `.example-card__editor-blank-answer`：填空题答案输入

作者态下真正的互斥关系是：

- `single / multi / flex` 显示题型胶囊 + 答案键
- `blank` 显示题型胶囊 + blank 答案输入

`zone2-example-card.css` 里必须额外保留：

```css
.example-card__editor-answer-key[hidden],
.example-card__editor-blank-answer[hidden] {
  display: none !important;
}
```

如果没有这条补丁，编辑模式的全局 `display:flex` 规则会把 hidden 顶掉，blank 题就会同时露出 A/B/C/D 和填空输入框。

### 5.2 多选题退出守卫

编辑模式退出前，运行时会巡检所有 `multi` 题：

- 如果正确答案少于 2 个，阻止退出编辑模式；
- 对应的 `.example-card__editor-multi-hint` 会打 `is-invalid` 与 `is-shaking`；
- 这条守卫通过 patch `editorCore.toggleEditMode()` 接入，因此 `example-card-runtime.js` 必须晚于 `editor-core.js` 加载。

### 5.3 填空题作者态持久化

blank 编辑不是简单改 DOM 文本，而是结构化作者态变更：

- 输入框修改时同步回 `.example-card__blank[data-correct-answer]`
- 再写入 `example-card-authoring:*` 本地快照
- 刷新后通过 `hydrateStoredAuthoringConfig()` 恢复 `questionType`、`correctValues`、`blankAnswers`

这里不能只依赖富文本 `data-edit-id` 恢复链，因为 blank 的正确答案并不直接写在可编辑 innerHTML 文本里。

## 六、持久化与恢复优先级

例题组件同时存在两类持久化面：

### 6.1 富文本内容恢复

- `stem / option / analysis` 这类正文内容走 `[data-edit-id]` 恢复链
- 恢复优先级：`localStorage` > `AnnotationStore.getInitData()`
- 这样才能避免“第一次刷新仍看到旧 sidecar，第二次才恢复本地内容”的错觉

### 6.2 作者态结构恢复

- 题型、正确答案、blank 标准答案走 `example-card-authoring:*`
- Key 由 `stem data-edit-id`、`data-card-id` 或题目 DOM key 推导
- 只保存：
  - `questionType`
  - `correctValues`
  - `blankAnswers`

### 6.3 学生态状态为什么不跨刷新保留

这是一条刻意的课堂语义：

- 学生作答态只存在于内存 `stateMap`
- 刷新页面后会回到“未作答、未提交”的初始课堂状态
- 这样一张卡片可反复用于讲解，不会把上一次演示的学生选择态带进下一轮

## 七、放映与步进合同

例题组件已经接入 `slides-runtime.js` 与 `page-richtext-annotation-runtime.js` 的专项分支：

- `ArrowDown / ArrowUp`：切换上一题 / 下一题，不在题卡边界翻整页
- `ArrowLeft / ArrowRight`：始终钉在当前显示题目的左栏 `.example-card__main`
- 普通页 authored fragment 只有在**当前题已提交**后才允许 reveal / hover cue
- 解析区 `.example-card__analysis` 明确排除在 ordinary fragment 一级宿主之外，避免把复盘文本错误并入题面步进队列

这条合同的结果是：

- 题前：只能做题，不会提前露出隐藏讲解
- 题后：左栏题面上的 fragment 才进入讲题节奏
- 解析区：只承担“查看解析”的静态补充，不抢占左右键步进

## 八、音效合同

`assets/example-card-audio.js` 是很薄的一层业务语义翻译：

- 组件运行时只上报“提交结果是否正确”
- 音频适配层再决定调用 `AudioRuntime.playGlobalCue('answer-correct')` 还是 `answer-wrong`

题内切换上一题 / 下一题则直接复用全局 `page-turn` cue。这样能保证：

- 鼠标点按钮与键盘 `↑↓` 是同一种课堂节奏声
- 不需要再为例题组件维护一套和翻页音效内容重复的独立素材

---

## 九、与 quiz-annotation 的边界

不要把 `.example-card` 当成“缩小版 quiz-annotation”。两者的系统边界不同：

- `.quiz-annotation`：整页阅读 + 批注 + 作答 + sidecar
- `.example-card`：单卡讲题 + 轻量作者态 + ordinary fragment 门禁

因此以下能力当前**不属于**例题组件：

- 中栏批注 bubble
- `text-anchor / answer-anchor / linkId` 双端点模型
- SVG 连线
- 阅读填空右栏判分槽位
- matching 拖拽答题

如果未来需要“例题 + 批注同页”，优先考虑在业务层组合两个组件，而不是继续把 `.example-card` 扩成第二套 quiz 系统。
