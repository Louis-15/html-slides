# 沉浸式逃逸组件 —— 开发文档

> **文档状态**：架构规则已落地  
> **最后更新**：2026-04-18  
> **适用范围**：所有会主动隐藏 Zone 1、让 Zone 2 独占整页空间的组件

---

## 一、什么是“沉浸式逃逸组件”

沉浸式逃逸组件，是指那些会主动触发“隐藏 Zone 1 标题栏、让 Zone 2 获得整页高度”的组件。

它们的共同目标不是“普通内容展示”，而是：

- 让某一页完全交给核心内容本身
- 取消标题栏对垂直空间的挤占
- 建立更强的视觉舞台感与专注度

在 html-slides 里，这类组件通常出现在以下场景：

- 总封面页
- 章节封面页
- 结尾金句页
- 二维码结束页
- 答题与批注组件这类需要大量可视空间的交互页

---

## 二、当前架构归属

架构重组之后，沉浸式逃逸相关代码不再混放在一个文件里，而是按组件类型拆分：

| 类型 | 归属文件 | 说明 |
|------|----------|------|
| 非答题类沉浸式组件结构 | `assets/zones/zone2-immersive-components.css` | 当前主要承载 `title-hero`，未来承载章节封面、结尾页等 |
| 答题与批注组件的沉浸式逃逸规则 | `assets/zones/zone2-quiz-annotation/quiz-layout.css` | 由答题组件独立维护自己的全屏逃逸规则 |
| Zone 2 通用布局 | `assets/zones/zone2-layout.css` | 继续保留 `layout-title` 等基础布局，不负责具体沉浸式组件结构 |

这意味着：

- “是否全屏”是组件级能力
- “如何居中、如何分栏”仍然是布局级能力
- “颜色与品牌表现”仍然只属于主题层

## 四、触发机制

### 4.1 当前机制

当前仓库主要使用 CSS `:has()` 来做零 JavaScript 的自动触发。例如答题与批注组件：

```css
.slide:has(.quiz-annotation) .slide-header {
  display: none !important;
}

.slide:has(.quiz-annotation) .slide-content {
  margin-top: 0;
  flex: 1;
  max-width: none;
  padding: 12px 0 0 0;
}
```

这种方案的优点：

- 不需要额外 JS 判断
- HTML 结构天然自描述
- 组件出现时自动生效，组件不存在时自动回退

### 4.2 未来建议

未来新增沉浸式组件时，优先使用“专属根类名 + `:has()`”方案，例如：

- `.chapter-hero`
- `.ending-quote`
- `.ending-qr`

不要把多个不同组件都粗暴挂在一个语义不清的通用类上，否则会弱化结构可读性。

## 五、空间策略

### 5.1 Zone 1 的处理

沉浸式逃逸的本质，是让以下关系成立：

- Zone 1 退出当前页
- Zone 2 接管被释放的垂直空间
- 组件在新的空间里重新组织自己的视觉重心

### 5.2 Logo 的处理

右上角品牌 Logo（`.branding`）是挂在 `<body>` 下的全局 fixed 元素，不属于 Zone 1。

因此，沉浸式逃逸时：

- Zone 1 可以隐藏
- Logo 继续保留
- 组件只需要处理与 Logo 的安全间距，不需要额外做结构解绑

### 5.3 `layout-title` 的定位

`layout-title` 是布局，不是沉浸式组件。

它继续保留在 `assets/zones/zone2-layout.css` 中，负责：

- 垂直居中
- 水平居中
- 文本对齐方式

而 `title-hero` 本身只负责封面内容的结构和字号。

这条边界必须长期保持，不要再把布局能力回灌进沉浸式组件文件。

## 六、什么时候应该做成沉浸式组件

满足以下任意两条，通常就值得考虑：

- 页面内容希望占满更多纵向空间
- 标题栏会明显干扰视觉主叙事
- 页面核心信息只有一个主题，需要强舞台感
- 页面包含复杂交互，标题栏会挤压关键操作区

不满足这些条件时，不要滥用沉浸式逃逸。普通内容页继续走标准 Zone 1 + Zone 2 架构，维护成本最低。

---

## 七、新增沉浸式组件的开发清单

1. 为组件定义明确的根类名，不要复用无语义的通用类。
2. 判断它属于“非答题类沉浸式组件”还是“答题与批注专项系统”。
3. 结构样式放到正确的 Zone 2 CSS 模块里。
4. 如需全屏逃逸，补上对应的 `:has()` 触发规则。
5. 确认 Logo 安全间距与顶部呼吸空间足够。
6. 更新相关开发者文档，避免新架构和旧文档重新失配。

---

## 八、一句话规则

沉浸式逃逸是组件级能力，不是布局级能力；触发条件跟着组件走，布局规则留在 Zone 2 基础层，主题表现继续留给主题层。
